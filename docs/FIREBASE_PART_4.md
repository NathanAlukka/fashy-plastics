# Firebase Part 4: Daily schedule lifecycle

Part 4 introduces one shared `daily_records/{YYYY-MM-DD}` document per working date.

## Status lifecycle

1. `draft` — visible to the Head only.
2. `published` — visible to the Head and active Workers.
3. `completed` — visible to the Head and active Workers; the day is closed by the Head.

Each record stores the date, creator UID/name, created time, last update time, publish time and completion time where applicable. Timestamps are generated by Firestore rather than the phone clock.

## Firebase setup

1. Complete Parts 1–3.
2. Replace the Firebase Console rules with the repository's latest `firestore.rules` and publish them.
3. Sign in as Head and select a date on Home.
4. Press **Create Draft**.
5. Open the operational tabs and prepare the local assignments.
6. Return Home and press **Publish**.
7. In another browser, sign in as Worker and select the same date. The published date should now be available.
8. In Head Mode, use **Complete Day** when appropriate.

## Security

- Only an active Head can read draft records.
- Only an active Head can create, update, publish, complete or delete daily records.
- Active Workers can read only records whose status is `published` or `completed`.
- Unauthenticated users cannot access daily records.

## Current boundary

Part 4 publishes the daily-record metadata and status. The detailed Work rows still use LocalStorage until Part 5, so a Worker on another device can discover that a schedule was published but will not receive the Work rows yet. Part 5 will move those Work assignments and results into Firestore.
